## 1. 처음 한 번만 하는 준비

### ① 설치

- [VS Code](https://code.visualstudio.com) 설치
- [Git](https://git-scm.com) 설치 (설치 후 VS Code를 껐다 켜기)

### ② VS Code에 GitHub 로그인

1. 왼쪽 아래 **사람 모양 아이콘(계정)** 클릭
2. **`Sign in with GitHub`** 선택
3. 브라우저가 열리면 승인하기

### ③ 저장소 내려받기 (Clone)

1. `Ctrl + Shift + P` → **`Git: Clone`** 입력 후 선택
2. 아래 주소 붙여넣기

   ```text
   https://github.com/ku-inthon-team08/git-practice.git
   ```
3. 저장할 폴더 선택 → 오른쪽 아래 **`Open`** 클릭

> 💡 Clone은 **딱 한 번만** 하면 돼요. 이후엔 Pull(받아오기)로 최신 상태를 맞춰요.

### ④ 내 이름·이메일 등록 (처음 커밋할 때 한 번)

커밋하다가 이름을 물어보면 아래 두 줄을 터미널(`` Ctrl + ` ``)에 입력해요.

```bash
git config --global user.name "내 이름"
git config --global user.email "내 이메일@example.com"
```

## 2. 기본 개념 3분 정리

| 용어 | 쉬운 설명 |
|------|-----------|
| **Repository (저장소)** | 프로젝트 파일과 변경 기록을 모아둔 폴더 |
| **Branch (브랜치)** | 원본을 건드리지 않고 작업하는 **나만의 작업 공간** |
| **Commit (커밋)** | 변경 내용을 저장하는 **스냅샷** (게임의 세이브 포인트) |
| **Push (푸시)** | 내 컴퓨터의 커밋을 GitHub로 **올리기** |
| **Pull (풀)** | GitHub의 최신 내용을 내 컴퓨터로 **받아오기** |
| **Pull Request (PR)** | "내 작업을 합쳐주세요!" 하는 **요청서** |
| **Merge (병합)** | 브랜치의 작업을 메인에 **합치기** |

### 🗺️ 파일이 이동하는 길

```text
 작업 폴더 ──스테이징(+)──▶ 스테이징 영역 ──커밋(✔)──▶ 내 컴퓨터 저장소 ──푸시──▶ GitHub
```

## 3. VS Code로 협업하기 (단계별)

### Step 0. 최신 상태로 맞추기 (작업 시작 전 필수!)

1. 왼쪽 아래 브랜치 이름이 `main`인지 확인
2. 소스 제어 패널(`Ctrl + Shift + G`) 위쪽 **`···`** 클릭 → **`Pull`**

> ✅ 작업 전에 항상 최신 코드를 받아요. 안 그러면 나중에 충돌이 많이 생겨요.

### Step 1. 내 브랜치 만들기

1. 왼쪽 아래 **브랜치 이름(`main`)** 클릭
2. 위에 뜨는 메뉴에서 **`+ Create new branch...`** 선택
3. 브랜치 이름 입력 후 `Enter`
   - 예시: `feature/로그인`, `fix/오타수정`, `docs/readme`

> 🚫 **`main`에서 직접 작업하지 않아요!** 왼쪽 아래 이름이 내 브랜치로 바뀌었는지 꼭 확인해요.

### Step 2. 코드 수정하기

평소처럼 파일을 편집하고 저장(`Ctrl + S`)해요.
수정한 파일은 소스 제어 패널의 **Changes** 목록에 나타나요.

| 표시 | 의미 |
|------|------|
| **M** (Modified) | 수정된 파일 |
| **U** (Untracked) | 새로 만든 파일 |
| **D** (Deleted) | 삭제된 파일 |

파일을 **클릭**하면 왼쪽(이전) / 오른쪽(현재)으로 바뀐 부분을 비교해서 볼 수 있어요.

### Step 3. 커밋하기 (저장 + 기록)

1. 소스 제어 패널의 파일 옆 **`+`** 클릭 (스테이징)
   - 모든 파일을 한 번에 담으려면 **Changes** 제목 옆 `+` 클릭
2. 위쪽 입력창에 **커밋 메시지** 작성 (예: `feat: 로그인 버튼 추가`)
3. **`✔ Commit`** 버튼 클릭

> 💡 작은 단위로 **자주** 커밋하는 게 좋아요.

### Step 4. GitHub에 푸시하기

- 처음 푸시할 때: **`Publish Branch`** 버튼 클릭
- 그 이후: **`Sync Changes`** 버튼 클릭 (푸시 + 풀을 한 번에)

### Step 5. Pull Request 만들기

1. GitHub 저장소 페이지로 이동 ([바로가기](https://github.com/ku-inthon-team08/git-practice))
2. 노란색 **`Compare & pull request`** 버튼 클릭
3. **제목**과 **설명**을 작성 (무엇을, 왜 바꿨는지)
4. 오른쪽 **Reviewers**에 팀원 지정
5. **`Create pull request`** 클릭

> 💡 VS Code 확장 프로그램 **GitHub Pull Requests**를 설치하면 VS Code 안에서도 PR을 만들 수 있어요.

### Step 6. 리뷰 받고 병합하기

- 팀원이 코드를 보고 코멘트를 남겨요.
- 수정 요청이 있으면 **같은 브랜치에서** 수정 → 커밋 → `Sync Changes` 하면 PR에 자동 반영돼요.
- 승인(Approve)을 받으면 **`Merge pull request`** 버튼으로 병합해요.

### Step 7. 병합 후 정리

1. 왼쪽 아래 브랜치 이름 클릭 → **`main`** 선택
2. 소스 제어 패널 `···` → **`Pull`**
3. 다음 작업은 다시 **Step 0**부터! 🔁

## 4. 충돌(Conflict) 해결하기

**충돌이란?** 같은 파일의 같은 부분을 두 사람이 동시에 고쳤을 때 Git이 "어느 쪽이 맞아요?" 하고 물어보는 상황이에요. **오류가 아니라 자연스러운 일**이니 당황하지 않아도 돼요!

### VS Code에서 해결하기

1. 소스 제어 패널의 **Merge Changes** 목록에서 충돌 파일 열기
2. 충돌 부분 위에 나타나는 버튼 중에서 선택

   | 버튼 | 의미 |
   |------|------|
   | **Accept Current Change** | 내 코드 유지 |
   | **Accept Incoming Change** | 팀원 코드 유지 |
   | **Accept Both Changes** | 둘 다 유지 |
   | **Compare Changes** | 두 내용 나란히 비교 |

3. 파일 저장 후 **`+`** 로 스테이징 → **`✔ Commit`** → **`Sync Changes`**

> 어떤 걸 남길지 헷갈리면 **작성한 팀원과 함께** 정해요. 🙌

## 5. 커밋 메시지 규칙

**"무엇을 했는지"가 한눈에 보이게** 써요.

```text
타입: 한 줄 요약
```

| 타입 | 언제 쓰나요? | 예시 |
|------|--------------|------|
| `feat` | 새 기능 추가 | `feat: 회원가입 폼 추가` |
| `fix` | 버그 수정 | `fix: 버튼 클릭 안 되는 문제 해결` |
| `docs` | 문서 수정 | `docs: README 사용법 추가` |
| `style` | 디자인/포맷 수정 (기능 변화 없음) | `style: 메인 색상 변경` |
| `refactor` | 코드 정리 (기능 변화 없음) | `refactor: 중복 함수 분리` |
| `chore` | 기타 설정 | `chore: .gitignore 추가` |

```text
✅ feat: 로그인 버튼 추가
✅ fix: 모바일에서 메뉴가 안 보이는 문제 수정

❌ 수정
❌ ㅇㅇ
❌ 이것저것 고침
```

## 6. 자주 하는 실수와 해결법

| 상황 | VS Code에서 해결하는 법 |
|------|-------------------------|
| 스테이징을 잘못한 파일이 있어요 | **Staged Changes**의 해당 파일 옆 **`−`** 클릭 |
| 수정한 내용을 되돌리고 싶어요 | **Changes**의 파일 옆 **되돌리기(↶)** 클릭 ⚠️ 저장 안 한 변경은 사라져요 |
| 방금 커밋을 취소하고 싶어요 (푸시 전) | `···` → **Commit** → **Undo Last Commit** |
| 엉뚱한 브랜치(`main`)에서 작업했어요 | 커밋 전이라면 새 브랜치를 만들어 이동하세요. 변경사항이 그대로 따라와요 |
| 지금 어느 브랜치인지 모르겠어요 | 왼쪽 아래 브랜치 이름 확인 |
| 푸시가 거절(rejected)됐어요 | `Sync Changes`(또는 `Pull`)로 최신 내용을 먼저 받고 다시 푸시 |
| 작업 중에 급하게 브랜치를 옮겨야 해요 | `···` → **Stash** → **Stash**로 임시 보관, 돌아와서 **Pop Latest Stash** |
| 커밋 기록을 보고 싶어요 | 소스 제어 패널 아래 **Graph(그래프)** 영역 확인 |

> 🚫 **강제 푸시(Force Push)는 팀원의 작업을 지울 수 있어요.** 팀원과 상의 없이 쓰지 않아요!

## 7. 명령어로 쓰는 법 (간단 소개)

VS Code 터미널(`` Ctrl + ` ``)에서도 같은 작업을 할 수 있어요. **버튼으로 하는 것과 결과가 같아요!**

```bash
git pull origin main                   # 최신 코드 받기
git switch -c feature/내작업           # 브랜치 만들고 이동
git status                             # 현재 상태 확인
git add .                              # 변경 파일 담기
git commit -m "feat: 로그인 버튼 추가"   # 커밋
git push -u origin feature/내작업      # 푸시
```

| VS Code 버튼 | 명령어 |
|--------------|--------|
| Pull | `git pull` |
| 브랜치 만들기 | `git switch -c 브랜치명` |
| 스테이징 `+` | `git add` |
| ✔ Commit | `git commit -m "메시지"` |
| Publish / Sync Changes | `git push` |

> 💡 막히면 `git status`부터! 지금 상태와 다음에 할 일의 힌트를 알려줘요.

## 8. 꼭 지켜요! 협업 약속

- ✅ **작업 시작 전** Pull로 최신 코드 받기
- ✅ **`main`에서 직접 작업하지 않기** — 항상 브랜치를 만들어서!
- ✅ **작은 단위로 자주 커밋**하기
- ✅ 커밋 메시지는 **무슨 일을 했는지** 알 수 있게 쓰기
- ✅ **PR로 리뷰**를 받은 뒤 병합하기
- ✅ 모르겠으면 **혼자 고민하지 말고 팀원에게 질문**하기 🙋
- ❌ 강제 푸시(Force Push) 함부로 쓰지 않기
- ❌ 비밀번호, API 키 같은 **민감한 정보는 절대 커밋하지 않기**
